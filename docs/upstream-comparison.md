## 3. 当前可以使用到什么程度

可以作为本地试读平台：真实采集累计入库 16 条，3 条取得模型结果，2 条进入精选；页面保留原始发布时间、来源和原文链接，未伪造今天新闻。AMD 与 vLLM 的精选在首页和全部动态可读，NVIDIA cuBLAS 25 分未入选，低于列表下限。桌面 1440px 与手机 390px 的首页、列表、两篇详情、主题、日报、热点共 14 项检查通过。

但不能据此认定无人值守运营通过：13 条尚无本次模型结果；数据库快照为 2 条 `analyzed`、14 条 `new`，后者包括已取得结果、随后又被队列重试的 NVIDIA 条目。模型输出数、公开展示数和任务完成数是不同指标。日报仍未发布，多源热点仍为空。持续采集、持续模型调用与发送阀门仍关闭，这符合用户当前选择。

既有测试：网页 61/61、备份恢复 14/14、无需数据库测试 274 项、HTTP 15 项通过；前次完整数据库测试 1128/1141，13 项宿主备份失败后由容器定向复验覆盖，未重新完整跑 1141 项。本轮是比较、只读复现与真实页面检查，没有把既有测试重写成“本轮全量通过”。

## 6. 推荐推进顺序与不应扩张的范围

1. 先修 R01/R02 与 R03：让企业识别、发布分类和完成状态可信。
2. 再解决 R04，并按现有预算完成受控小批采集到展示；持续运行仍以用户授权为前提。
3. 补 R05 的关键覆盖，同时做 R06 标注校准；以内容价值和漏报率决定源与阈值。
4. 完成 R07 的真实多源聚合、日报和周/月报验证，再考虑扩大规模。
5. 受控同步上游，完成 R09 的迁移和运行说明。

芯片产品参数库、自动性能排名、CRM、客户项目管理、注册/权限/SSO、长篇自动研究报告不在一期范围，原开源框架也未提供完整的芯片行业版本。它们不能算本次漏做；在资讯质量稳定前加入，会扩大维护成本而不解决当前主要问题。

本次评估由当前执行 Agent 完成，没有虚构独立审查或额外多 Agent 验收。报告中的已验证事实、静态推断、运营缺口和下一步建议分别标明；没有把“代码存在”“页面返回 200”当作产业内容正确性证明。
